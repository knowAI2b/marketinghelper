# 第三方 Agent 工具集成计划书

## 1. 背景与目标

### 1.1 背景
当前小红书助手项目已有完整的意图识别 → Planner → 多 Agent 执行 → Verifier 流程，但核心能力依赖占位实现。现需引入第三方 Agent 框架（nanobot/nanoclaw）来增强：
- 意图识别与需求澄清
- 任务规划与调度
- Agent 执行能力

**重要**：本项目采用"核心+插件"架构，未来将支持多平台（小红书、微信、TikTok、朋友圈等），Agent 后端作为核心能力层，平台特性作为插件扩展。

### 1.2 目标

#### 核心目标
1. **配置化选择**：通过环境变量选择使用 `native`（现有实现）或 `nanobot` 作为 Agent 后端
2. **优先支持 nanobot**：首先完整实现 nanobot 集成
3. **平滑嵌合**：保持现有 API 接口不变，内部实现可切换
4. **渐进式迁移**：支持混合模式，部分模块用 nanobot，部分保留原有实现
5. **多平台扩展**：Agent 后端设计为平台无关，支持未来接入微信、TikTok 等平台

#### MCP Server 目标（新增）
6. **MCP 协议支持**：作为 MCP Server，暴露核心能力供外部工具调用
7. **多客户端支持**：支持 OpenClaw（龙虾工具）、Claude Desktop、Cursor 等 MCP 客户端
8. **双向集成**：既能消费外部 MCP 服务（作为 Client），也能提供服务（作为 Server）

    """意图识别结果协议"""
    demand_summary: str

    ambiguous_intent: str | None

class PlanResult(Protocol):
    """任务规划结果协议"""
    steps: list[dict[str, Any]]
    reasoning: str | None

class ExecutionResult(Protocol):
    """执行结果协议"""
    success: bool
    output: Any
    error: str | None
    step_id: str | None

class AgentBackend(ABC):
    """Agent 后端抽象基类"""

    @abstractmethod
    async def understand_intent(
        self,
        user_input: str,
        account_context: dict[str, Any]
    ) -> IntentOutputData:
        """理解用户意图"""
        ...

    @abstractmethod
    async def plan_tasks(
        self,
        intent_output: dict[str, Any],
        account_context: dict[str, Any]
    ) -> PlanOutputData:
        """规划任务步骤"""
        ...

    @abstractmethod
    async def execute_step(
        self,
        step: dict[str, Any],
        state: dict[str, Any]
    ) -> ExecutionOutputData:
        """执行单个步骤"""
        ...

    @abstractmethod
    async def clarify(
        self,
        user_input: str,
        context: dict[str, Any]
    ) -> ClarificationOutputData:
        """需求澄清对话"""
        ...

    # 可选方法（有默认实现）
    async def health_check(self) -> bool: ...
    async def close(self) -> None: ...

#### 3.3.1 MCP Server 主入口

```python
"""MCP Server: 将营销助手能力暴露为 MCP 工具。"""
from __future__ import annotations

import logging
from typing import Any

from mcp.server import Server
from mcp.server.sse import SseServerTransport
from mcp.server.stdio import StdioServerTransport
from mcp.types import Tool, Resource, Prompt

from xhs_assistant.backends.manager import BackendManager
from xhs_assistant.shared.config import config

logger = logging.getLogger(__name__)


class XhsMCPServer:
    """小红书营销助手 MCP Server。

    支持两种传输方式：
    - stdio: 标准输入输出，适合命令行启动
    - sse: Server-Sent Events，适合远程访问

    使用示例：
        # stdio 模式
        python -m xhs_assistant.mcp.server

        # SSE 模式
        XHS_MCP_TRANSPORT=sse python -m xhs_assistant.mcp.server
    """

    def __init__(self) -> None:
        self.config = config.mcp_server
        self.server = Server(self.config.server_name)
        self.backend = BackendManager.get_backend()

        self._register_tools()
        self._register_resources()
        self._register_prompts()

    def _register_tools(self) -> None:
        """注册 MCP Tools。"""
        from xhs_assistant.mcp.tools import (
            register_content_generate_tool,
            register_topic_plan_tool,
            register_account_strategy_tool,
            register_ads_plan_tool,
            register_content_evaluate_tool,
            register_clarify_tool,
        )

        register_content_generate_tool(self.server, self.backend)
        register_topic_plan_tool(self.server, self.backend)
        register_account_strategy_tool(self.server, self.backend)
        register_ads_plan_tool(self.server, self.backend)
        register_content_evaluate_tool(self.server, self.backend)
        register_clarify_tool(self.server, self.backend)

    def _register_resources(self) -> None:
        """注册 MCP Resources。"""
        from xhs_assistant.mcp.resources import (
            register_account_info_resource,
            register_template_resource,
        )

        register_account_info_resource(self.server)
        register_template_resource(self.server)

    def _register_prompts(self) -> None:
        """注册 MCP Prompts。"""
        from xhs_assistant.mcp.prompts import (
            register_marketing_prompts,
        )

        register_marketing_prompts(self.server)

    async def run_stdio(self) -> None:
        """以 stdio 模式运行。"""
        async with StdioServerTransport() as transport:
            await self.server.run(transport)

    async def run_sse(self) -> None:
        """以 SSE 模式运行。"""
        from starlette.applications import Starlette
        from starlette.routing import Route

        sse = SseServerTransport(f"http://{self.config.sse_host}:{self.config.sse_port}/messages")

        async def handle_sse(request):
            async with sse.connect_sse(request.scope, request.receive, request._send) as streams:
                await self.server.run(streams[0], streams[1], self.server.create_initialization_options())

        app = Starlette(
            routes=[
                Route("/sse", endpoint=handle_sse),
                Route("/messages", endpoint=sse.handle_post_message, methods=["POST"]),
            ]
        )

        import uvicorn
        config = uvicorn.Config(
            app,
            host=self.config.sse_host,
            port=self.config.sse_port,
            log_level="info"
        )
        server = uvicorn.Server(config)
        await server.serve()

    async def run(self) -> None:
        """根据配置运行服务器。"""
        if self.config.transport == "stdio":
            await self.run_stdio()
        elif self.config.transport == "sse":
            await self.run_sse()
        else:
            raise ValueError(f"Unknown transport: {self.config.transport}")


# 入口点
async def main() -> None:
    server = XhsMCPServer()
    await server.run()


if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

def register_content_generate_tool(server: "Server", backend: "AgentBackend") -> None:
    """注册内容生成工具。"""

    @server.call_tool()
    async def xhs_content_generate(
        demand: str,
        platform: str = "小红书",
        industry: str | None = None,
        goal: str | None = None,
        topic: str | None = None,
        content_form: str = "图文",
        account_stage: str | None = None,
        account_persona: str | None = None,
    ) -> list[TextContent]:
        """生成小红书内容。

        Args:
            demand: 用户需求描述
            platform: 发布平台（小红书/抖音/微信等）
            industry: 行业领域（美妆/美食/穿搭等）
            goal: 营销目标（涨粉/种草/转化等）
            topic: 内容主题
            content_form: 内容形式（图文/视频）
            account_stage: 账号阶段（起号/冷启动/放量/变现）
            account_persona: 账号人设

        Returns:
            生成的内容，包含标题、正文、标签等
        """
        account_context = {
            "platform": platform,
            "industry": industry,
            "goal": goal,
            "topic": topic,
            "content_form": content_form,
            "account_stage": account_stage,
            "account_persona": account_persona,
        }

        # 意图识别
        intent = await backend.understand_intent(demand, account_context)

        # 执行内容生成
        step = {
            "step_id": "s1",
            "agent": "内容生成",
            "input_summary": demand,
        }
        state = {"intent_output": intent.__dict__}
        result = await backend.execute_step(step, state)

        return [TextContent(
            type="text",
            text=json.dumps({
                "success": result.success,
                "content": result.output,
                "error": result.error,
            }, ensure_ascii=False, indent=2)
        )]

                    "default": "小红书"

### 9.1 为什么使用 LiteLLM 而非 nanobot AgentLoop？

**原因**:
1. **简化架构**: LiteLLM 直接调用，无需处理复杂的事件循环
2. **多提供商支持**: LiteLLM 支持 100+ LLM 提供商
3. **维护成本低**: 减少第三方依赖
4. **性能更好**: 无额外抽象层开销

### 9.2 槽位澄清策略

**设计原则**:
1. **避免重复澄清**: 已有槽位信息不重复询问
2. **优先级顺序**: platform > account_persona > account_stage > industry > goal > topic
3. **最小澄清**: 有效槽位 >= 2 且有 platform 时，跳过澄清

### 9.3 MCP Server 传输方式选择

| 传输方式 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| **stdio** | Claude Desktop、Cursor | 简单、安全、本地 | 仅支持本地 |
| **sse** | OpenClaw、Web 客户端 | 支持远程、易集成 | 需要网络配置 |

### 9.4 MCP Tools 设计原则

1. **单一职责**: 每个 Tool 只做一件事
2. **清晰命名**: 使用 `xhs_` 前缀，语义明确
3. **完整 Schema**: 定义清晰的输入输出 schema
4. **错误处理**: 返回结构化错误信息
5. **幂等性**: 相同输入产生相同输出
