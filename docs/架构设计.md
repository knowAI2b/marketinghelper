# 小红书助手系统架构设计文档

## 1. 引言

### 1.1 文档目的

本文档描述小红书助手（XHS Assistant）系统的技术架构设计，为开发、运维和后续扩展提供架构指导。

### 1.2 系统概述

小红书助手是一个面向小红书平台的内容营销辅助系统，通过多 Agent 协作实现账号战略规划、选题策划、内容生成、投流规划等功能。系统采用 LangGraph 进行工作流编排，支持多种 LLM 后端的灵活切换。

### 1.3 设计目标

| 目标 | 描述 |
|------|------|
| 可扩展性 | 支持多种 Agent 框架和 LLM 后端的即插即用 |
| 可配置性 | 通过环境变量灵活配置后端选择，无需修改代码 |
| 可观测性 | 完整的日志体系，支持问题追踪和行为分析 |
| 高内聚低耦合 | 模块边界清晰，接口定义明确 |

## 3. 核心模块设计

### 3.1 后端抽象层 (backends/)

#### 3.1.1 设计意图

后端抽象层解决以下问题：
- **框架锁定风险**：避免系统与特定 Agent 框架（LangGraph/LangChain）强绑定
- **模型灵活性**：支持在不同 LLM 提供商之间切换
- **测试便利性**：可以方便地使用 Mock 后端进行测试
- **渐进迁移**：支持新老实现并存，逐步迁移

#### 3.1.2 模块结构

```
backends/
├── __init__.py          # 公共接口导出
├── base.py              # 抽象基类与协议定义
├── manager.py           # 后端管理器（单例、工厂）
├── native_backend.py    # Native 实现（LangGraph）
└── nanobot_backend.py   # Nanobot 实现（LiteLLM）
```

#### 3.1.3 核心接口设计

**AgentBackend 抽象基类**

```python
class AgentBackend(ABC):
    """Agent 后端抽象基类，定义统一的 Agent 能力接口。"""

    @abstractmethod
    async def understand_intent(
        self,
        user_input: str,
        account_context: dict[str, Any],
    ) -> IntentOutputData:
        """意图理解：解析用户自然语言输入，提取结构化意图。"""
        ...

    @abstractmethod
    async def plan_tasks(
        self,
        intent_output: dict[str, Any],
        account_context: dict[str, Any],
    ) -> PlanOutputData:
        """任务规划：根据意图生成可执行的任务步骤列表。"""
        ...

    @abstractmethod
    async def execute_step(
        self,
        step: dict[str, Any],
        state: dict[str, Any],
    ) -> ExecutionOutputData:
        """步骤执行：执行单个任务步骤，返回执行结果。"""
        ...

    @abstractmethod
    async def clarify(
        self,
        user_input: str,
        context: dict[str, Any],
    ) -> ClarificationOutputData:
        """需求澄清：当意图不明确时，生成澄清问句。"""
        ...
```

**结果协议（Protocol）**

使用 Python Protocol 定义接口契约，确保不同后端返回统一的数据结构：

```python
class IntentResult(Protocol):
    """意图识别结果协议。"""
    demand_summary: str              # 需求摘要
    intent_type: str                 # 意图类型
    slots: dict[str, Any]            # 槽位键值对
    needs_clarification: bool        # 是否需要澄清
    clarification_question: str | None
    missing_slots: list[str] | None
    suggested_agents: list[str]
```

#### 3.1.4 后端管理器

**职责**：
- 根据配置创建后端实例
- 单例模式管理后端生命周期
- 支持模块级别的后端覆盖

**设计模式**：工厂模式 + 单例模式

```python
class BackendManager:
    _instances: dict[str, AgentBackend] = {}

    @classmethod
    def get_backend(cls, backend_type: str | None = None) -> AgentBackend:
        """获取后端实例（单例）。"""
        if backend_type is None:
            backend_type = config.agent_backend.backend_type
        if backend_type not in cls._instances:
            cls._instances[backend_type] = cls._create_backend(backend_type)
        return cls._instances[backend_type]

    @classmethod
    def get_intent_backend(cls) -> AgentBackend:
        """获取意图识别后端（支持模块级覆盖）。"""
        backend_type = config.agent_backend.get_effective_backend("intent")
        return cls.get_backend(backend_type)
```

#### 3.1.5 后端实现对比

| 特性 | NativeBackend | NanobotBackend |
|------|---------------|----------------|
| 底层框架 | LangGraph + LangChain | LiteLLM 直接调用 |
| 复杂度 | 高（完整工作流编排） | 低（简单直接） |
| 灵活性 | 支持复杂状态机 | 适合简单调用场景 |
| 性能开销 | 较高 | 较低 |
| 模型支持 | 受 LangChain 限制 | 支持所有 LiteLLM 兼容模型 |
| 适用场景 | 复杂多步骤工作流 | 快速响应、简单任务 |

### 3.2 配置系统 (shared/config.py)

#### 3.2.1 设计原则

- **环境变量驱动**：所有配置通过环境变量注入，支持 12-Factor App
- **类型安全**：使用 dataclass 定义配置结构，提供类型提示
- **默认值合理**：提供合理的默认值，减少必填配置项
- **配置分层**：支持全局配置和模块级配置覆盖

#### 3.2.2 配置结构

```
Config
├── rednote: RednoteConfig
│   ├── service_url: str
│   ├── auth_token: str
│   ├── enabled: bool
│   └── timeout: int
│
└── agent_backend: AgentBackendConfig
    ├── backend_type: str          # 全局后端类型
    ├── nanobot_*                  # Nanobot 相关配置
    ├── intent_backend: str | None # 模块级覆盖
    ├── planner_backend: str | None
    └── executor_backend: str | None
```

#### 3.2.3 模块级覆盖机制

允许不同模块使用不同的后端实现：

```python
def get_effective_backend(self, module: str) -> str:
    """获取模块的有效后端类型。"""
    override_map = {
        "intent": self.intent_backend,
        "planner": self.planner_backend,
        "executor": self.executor_backend,
    }
    override = override_map.get(module)
    return override if override else self.backend_type
```

### 3.3 日志系统 (shared/logging_config.py)

#### 3.3.1 日志分类

| 日志类型 | 文件 | 用途 | 格式 |
|----------|------|------|------|
| 应用日志 | `logs/app.log` | 记录系统运行状态、错误信息 | 时间戳 + 级别 + 模块 + 消息 |
| 用户行为日志 | `logs/user_action.log` | 记录用户操作、API 调用 | 时间戳 + 级别 + 结构化字段 |

#### 3.3.2 日志格式规范

**应用日志格式**：
```
%(asctime)s | %(levelname)-8s | %(name)s:%(lineno)d | %(message)s
```

**用户行为日志格式**：
```
action=<action> | user_id=<user_id> | session_id=<session_id> | <details>
```

#### 3.3.3 日志轮转策略

- 单文件最大 10MB
- 应用日志保留 5 个备份
- 用户行为日志保留 10 个备份

### 3.4 Agent 注册表 (agents/registry.py)

#### 3.4.1 Agent 定义

系统定义 5 个核心 Agent：

| Agent 名称 | 职责 | 输入 | 输出 |
|------------|------|------|------|
| 账号战略 | 账号定位、人设规划 | 行业、目标 | 账号策略文档 |
| 选题策划 | 内容选题建议 | 账号策略、目标 | 选题列表 |
| 内容生成 | 生成小红书内容 | 选题、风格 | 图文/视频内容 |
| 投流规划 | 广告投放策略 | 内容、预算 | 投流方案 |
| 内容评估 | 内容质量检验 | 生成内容 | 评估报告 |

#### 3.4.2 注册表模式

```python
class AgentRegistry:
    """Agent 注册表，管理所有 Agent 实例。"""

    _agents: dict[str, type[BaseAgent]] = {}

    @classmethod
    def register(cls, name: str, agent_class: type[BaseAgent]):
        """注册 Agent。"""
        cls._agents[name] = agent_class

    @classmethod
    def get(cls, name: str) -> BaseAgent:
        """获取 Agent 实例。"""
        if name not in cls._agents:
            raise ValueError(f"Unknown agent: {name}")
        return cls._agents[name]()
```

## 7. 扩展指南

### 7.1 添加新的后端实现

1. 在 `backends/` 目录创建新的后端文件
2. 继承 `AgentBackend` 抽象基类
3. 实现所有抽象方法
4. 在 `manager.py` 中注册新后端

```python
# backends/my_backend.py
class MyBackend(AgentBackend):
    async def understand_intent(self, user_input, account_context):
        # 实现逻辑
        return IntentOutputData(...)

# backends/manager.py
@classmethod
def _create_backend(cls, backend_type: str) -> AgentBackend:
    if backend_type == "my_backend":
        from .my_backend import MyBackend
        return MyBackend()
```

### 7.2 添加新的 Agent

1. 在 `agents/` 目录创建 Agent 文件
2. 继承 `BaseAgent` 或实现相应接口
3. 使用 `@AgentRegistry.register` 装饰器注册

```python
@AgentRegistry.register("新Agent")
class NewAgent(BaseAgent):
    def run(self, input_data: dict) -> dict:
        # 实现逻辑
        return {"result": "..."}
```
